## 1. 产品概述

### 1.1 一句话描述

面向普通个人的 AI 理财规划工具，5 分钟输入生成个性化资产配置方案，并提供持续的 AI 陪伴和调仓提醒。

### 1.2 要解决的问题

**核心矛盾：普通人需要理财指导，但专业服务太贵太复杂。**

- 中国个人可投资资产规模超过 200 万亿元，但 80% 的理财用户从未接受过专业顾问服务
- 银行理财经理服务高端客户，普通用户只能自己摸索
- 互金平台（蚂蚁财富、且慢等）产品众多但缺乏个性化全局配置
- 用户在市场波动时容易恐慌性操作，缺乏理性引导

### 1.3 解决方案

用户只需回答 5 个关于自己的问题（年龄、收入、支出、风险偏好、投资期限），系统通过 4 个 AI Agent 协作——

- **分析你的财务画像**：你处于什么人生阶段？能承受多大风险？
- **研判当前市场**：股票、债券、商品现在是什么情况？
- **生成配置方案**：基于经典的"四笔钱"框架，给出活钱/稳健/长期/保障的分配比例
- **持续陪伴**：AI 理解你的上下文，随时可以提问，有问题可以主动提醒

### 1.4 产品定位

```
个人理财教育 + AI 配置建议工具
（不做交易、不做资金托管、不推荐具体产品）
```

### 1.5 竞品分析

| 产品 | 核心功能 | 本产品差异 |
|------|---------|----------|
| 蚂蚁财富 | 基金销售平台，千人千面推荐 | 全局资产配置视角，不是单品推荐 |
| 且慢 | 基金组合订阅，四笔钱框架 | 个性化 AI 生成 vs 标准化组合 |
| 蛋卷基金 | 指数基金定投 | 多资产类别 + 全生命周期 |
| 传统理财顾问 | 面对面服务，年费数千 | 零成本 + 24小时可用 + 无推销压力 |

## 2. 用户分析

### 2.1 目标用户画像

#### 画像A：理财小白 — 李明

| 属性 | 描述 |
|------|------|
| 年龄 | 25-30岁 |
| 职业 | 互联网/科技行业，程序员或产品岗 |
| 月收入 | 15K-25K |
| 理财现状 | 钱放余额宝，偶尔买点基金但不敢多投，担心亏损又怕通胀 |
| 痛点 | "我知道该理财，但不知道从哪开始" |
| 目标 | 建立第一份理财方案，养成投资习惯 |

#### 画像B：进阶白领 — 张薇

| 属性 | 描述 |
|------|------|
| 年龄 | 30-40岁 |
| 职业 | 企业中层，已婚有孩 |
| 月收入 | 25K-50K |
| 理财现状 | 有些基金和股票，凭感觉配置，行情不好时容易慌 |
| 痛点 | "我的配置合理吗？现在该不该调整？" |
| 目标 | 优化现有资产配置，获得持续的市场分析和建议 |

#### 画像C：家庭支柱 — 王磊

| 属性 | 描述 |
|------|------|
| 年龄 | 35-45岁 |
| 职业 | 传统行业，有房贷和子女教育压力 |
| 月收入 | 20K-35K |
| 理财现状 | 主要资产在房产，金融资产以存款和银行理财为主 |
| 痛点 | "万一家里出什么事，钱够不够？怎么配置保障？" |
| 目标 | 增加保障配置，确保家庭财务安全 |

### 2.2 核心使用场景

**场景1：首次理财规划（画像A）**

> 李明周五晚上在家，花5分钟完成测评，等了约1分钟看到完整的配置方案。他对着饼图和产品列表研究了一晚上，第二天开始按方案调整自己的资金分配。

**场景2：市场波动时的安抚（画像B）**

> 张薇看到新闻里沪深300大跌，打开产品找 AI 助手问"今天跌了这么多，我的方案要调整吗？"AI 告诉她压力测试显示极端情况也能恢复，建议保持方案不变，张薇放心了。

**场景3：定期检查（画像C）**

> 王磊每季度登录一次，查看是否有偏离需要调整。他点击"检查再平衡"，系统告诉他仓位偏离只有2%，在5%阈值内，不需要调整。

## 3. 功能需求

### 3.1 账号体系

| ID | 功能 | 描述 | 验收标准 | 优先级 |
|----|------|------|----------|--------|
| ACC-01 | 注册 | 输入用户名、密码创建账号，邮箱选填 | 用户名3-20位，密码≥6位，重复用户名提示 | P0 ✅ |
| ACC-02 | 登录 | 用户名+密码登录 | 正确密码登录成功，错误密码提示 | P0 ✅ |

### 3.2 风险测评

| ID | 功能 | 描述 | 验收标准 | 优先级 |
|----|------|------|----------|--------|

| RISK-02 | 基本信息 | 输入年龄、月收入、月支出 | 年龄18-80限制，金额≥0 | P0 ✅ |
| RISK-03 | 风险偏好 | 选择保守/稳健/进取 | 显示每个选项的简要说明 | P0 ✅ |

### 3.3 策略生成核心流程

| ID | 功能 | 描述 | 验收标准 | 优先级 |
|----|------|------|----------|--------|
| GEN-01 | 触发生成 | 测评完成后点击按钮启动 AI 分析 | 按钮点击后立即跳转结果页 | P0 ✅ |

## 4. 非功能性需求

### 4.1 性能要求

| 指标 | 目标值 | 测量方式 |
|------|--------|----------|
| 策略生成全流程 | ≤ 120秒 | 端到端计时（4个Agent顺序执行） |
| 页面首屏加载 | ≤ 3秒 | Lighthouse First Contentful Paint |
| AI 对话回复 | ≤ 15秒 | 从发送到收到回复的墙钟时间 |
| 市场数据获取 | ≤ 10秒/源 | 单个AKShare数据源超时阈值 |

### 4.2 可用性要求

| 要求 | 描述 |
|------|------|
| 空状态覆盖 | 所有数据依赖页面都有空状态引导，不允许空白页 |
| 中文错误提示 | 所有错误提示用中文，说明原因和建议操作 |
| 进度反馈 | 所有超过3秒的操作有进度指示（进度条或文字提示） |
| 表单容错 | 测评表单预填默认值，可快速提交 |

### 4.3 数据要求

| 要求 | 描述 |
|------|------|
| 用户数据持久化 | 注册信息、测评记录、生成方案保存到 PostgreSQL，服务重启不丢失 |
| 市场数据优先级 | AKShare 实时数据 → 硬编码默认值，降级不影响主流程 |
| 对话不持久化 | AI 对话历史暂不存库，仅保留最近6条在内存中 |

### 4.4 安全要求

| 要求 | 描述 |
|------|------|
| 密码加密 | bcrypt 哈希存储，不存明文 |
| 接口鉴权 | 所有非公开API需 JWT Bearer Token |
| 前端路由保护 | 未登录用户重定向到登录页 |
| 无用户隐私数据外传 | 用户财务数据不发给第三方（仅DeepSeek API用于AI分析） |

## 5. 边界与约束

### 5.1 本期不做（Out of Scope for v1.1）

| 项目 | 原因 | 计划 |
|------|------|------|
| 邮箱验证 | 注册量小时非必需 | v1.2 |
| 密码重置 | 用户量小时可人工处理 | v1.2 |
| 真实交易/持仓对接 | 需要合规牌照 | v2.0 |
| 移动端原生App | 开发成本高 | 先用响应式Web |
| WebSocket实时推送 | 当前轮询可满足需求 | v1.2 |
| 主动消息通知（邮件/短信） | 需搭建消息通道 | v1.2 |
| 多语言支持 | 目标用户为中文用户 | 暂不规划 |

### 5.2 已知局限

- AI 配置建议基于 DeepSeek 模型，不构成专业投资建议（需免责声明）
- 市场数据依赖 AKShare 免费接口，在交易时段可能有延迟
- 四笔钱金额基于用户自报的收支推算，非真实账户数据
- 压力测试为历史情景回测，不代表未来表现

## 6. 术语表

| 术语 | 定义 |
|------|------|
| 四笔钱 | 资产配置框架：活钱（流动性）、稳健（保值增值）、长期（高收益）、保障（风险兜底） |
| 用户画像 | AI 对用户财务状态的综合分析，包括生命周期阶段、风险承受能力、财务健康评分等 |
| 适当性约束 | 根据用户风险等级强制限制权益类资产配置上限的规则引擎 |
| 再平衡 | 当实际持仓偏离目标配置超过阈值时，重新调整到目标比例 |
| 渐进式披露 | 生成方案时按 Agent 完成顺序逐步展示结果，而非等待全部完成后一次性显示 |
